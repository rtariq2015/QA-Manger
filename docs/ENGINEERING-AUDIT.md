# Offline workstation engineering audit

Baseline: **5.6.0**, commit `6b51f4c3223b9cbe051dd9c9e502c10954f8e603`. Audit started 2026-11-16. Development branch: `engineering/offline-workstation-audit`. This is an incremental engineering change, not a new release or a replacement application.

## Scope and existing implementation

The review covers the tracked application source, launchers, configuration schema, documentation, current screenshots/design previews, packaging and CI, and the automated test sources. Historical test reports describe previous execution; they are not fresh validation of this branch.

## Prioritized assessment and practical plan

Priority expresses the impact of the observed implementation, not a claim that every candidate is a production incident. Implementation status and fresh results are recorded separately below and in the branch validation report.

| Priority | Current implementation and problem | Recommended change | Expected benefit | Compatibility risk / decision |
| --- | --- | --- | --- | --- |
| P1 | `filteredRecords` sorts and filters the entire library on every search input; `renderReports` constructs every matching row. Exports already bounds its preview to 12 rows. A 20,000-record result can create hundreds of thousands of DOM nodes. | Cache normalized/sorted metadata per record revision, debounce Reports/Exports text searches, and render a bounded Reports page while retaining the complete matching set for exports. Measure 1,367 and 20,000 synthetic records before/after. | Less main-thread work, memory and input delay; exports still contain all matching reports. | Low–medium: navigation, filter invalidation, selection and export scope require regressions. Implement first. |
| P1 | Snapshot refresh replaces report/review DOM even when record content is unchanged. Previous focus restoration exists and must remain. | Reuse unchanged record views and preserve focused controls, drafts, selected rows and open groups. | Background progress should not repeatedly rebuild a large library or interrupt typing. | Medium: compare all visible metadata, not only IDs/counts. Test changed records and unchanged snapshots. |
| P1 | `PdfPreview.psm1` reconstructs the complete dashboard for each page; the PDF endpoint does the same for one record. Monthly coverage/attention projections are unrelated to that lookup. | Resolve IDs from fresh, validated core archive records, preserving direct-path, membership and byte-hash validation. | Reduce preview overhead without caching away integrity checks. | Low–medium: central read-only helper; native PDF regression and synthetic metadata benchmark. |
| P1 | Upgrade validates source paths but does not consistently reject linked target/root/backup paths before mutation. Rollback can leave a newly introduced root file after later failure. | Preflight direct target paths and track/restore both existing and newly introduced files on rollback. | Fail safely before mutation and recover the prior program more completely. | Medium: synthetic failed-install, link and preservation tests required. |
| P1 | Backup validation is less strict about Windows names, duplicate/link entries than update validation; restore reopens a validated ZIP. | Apply explicit safe entry validation and keep the validated input stable through extraction. | Reject ambiguous/unsafe archives and avoid validating one file then restoring another. | Medium: preserve existing valid backup format, hashes, limits and new-folder restore. |
| P1 | Core state reads validate individual records but permit duplicate IDs/destination paths; downstream consumers handle ambiguity inconsistently. | Reject ambiguous state centrally without changing the original state file. | Avoid counting, selecting or mutating an ambiguous archive. | Low–medium: legitimate same-name/same-byte reports at distinct destinations must remain valid. |
| P1 | Many secondary labels/actions are 7–11 px; Review forces a viewport-height layout and hides overflow in a fixed control rail. Short effective viewports at high scaling can make actions inaccessible. | Raise text sizes/contrast, provide a compact density choice, and let the review layout scroll/stack when necessary. | More readable and reachable controls on hospital monitors. | Low–medium: test all tabs and effective 100/125/150/200% viewports; retain wide-screen PDF space. |
| P2 | Some dialogs lack accessible names, Settings tab semantics are incomplete, and PDF scrolling lacks a keyboard focus target. | Add dialog labels, coherent tab roles/keyboard behavior, focus indicators and named PDF scroll regions. | Better keyboard and assistive-technology access. | Low: keep IDs/action interfaces and meaningful existing button labels. |
| P2 | List statuses say “Approved”/“Disapproved” without naming the filing decision, despite explicit notices elsewhere. | Use filing-specific status/progress terminology while retaining saved action/history schema. | Avoid implying clinical approval or measured QA pass/fail. | Low: no data migration or clinical evidence changes. |
| P2 | Windows validation runs automatically only on main; a single global concurrency group can cancel unrelated branches. | Add ordinary `pull_request` validation and scope concurrency to the branch/ref; retain read-only permissions. | Reviewable native checks before merge, independent branch work. | Low: no release workflow or elevated pull-request execution. |
| P2 | Native CI stops at the first failed PowerShell suite and skips independent validation after browser failures. | Continue independent suites, retain a failing aggregate result and gate checks on successful host/reader builds. | More complete failure evidence without hiding failed checks. | Low: extra CI time, no assertion changes or elevated permissions. |
| P2 | Classic still displays 4.4.1 while the release/browser baseline is 5.6.0. | Correct existing display literals; defer a shared version-source refactor. | Consistent fallback/version diagnostics. | Low: text only; verify WPF layout natively. |
| P2 | Smoke documentation mixes browser filing with Classic named clinical evidence review, and points Monthly setup at legacy Advanced controls. | Describe current browser and Classic formal-evidence workflows separately. | Staff/testers can follow the correct workflow without extra approval fields. | Low; documentation only. |
| P2 | The generated offline HTML folder navigator embeds every library row and searches the entire DOM; this is independent of the main app. | Measure a separately bounded offline navigator without dropping complete exported inventories. | Future smoother manager browsing at very large archive sizes. | Deferred: preserve current ordinary-folder navigation and complete offline exports. |
| P2 | Monthly setup checks history dates/duplicates, but central configuration validation does not enforce the full imported-history schema. | Design backward-compatible validation/migration for imported historical settings before centralizing it. | Consistent fail-safe configuration handling. | Deferred: avoid rejecting otherwise usable legacy evidence/settings without an explicit migration. |
| P1 | The derived master CSV quotes fields but does not neutralize spreadsheet formula prefixes in names/reviewer text; the authoritative JSON is separate. | Escape spreadsheet-active string cells in the CSV projection only; keep JSON and review evidence exact. | Safer spreadsheet viewing without changing report identity or saved clinical fields. | Low: preserve columns/order and verify normal cells plus formula-like fixtures. |
| P2 | Existing analysis already has AutoAnalyze, BelowNormal priority, Pause/Resume/Stop, one-PDF helpers and a 200 ms yield. | First measure the UI and metadata improvements; use existing pause/defer controls. Add a separate Low Resource Mode only if measurements justify another policy. | Avoid duplicate settings with unclear effects. | Defer new scheduling behavior; no safety limit increase. |
| P2 | Read-only host endpoints can start independent PowerShell workers. The viewer already limits concurrent requests to two. | Measure concurrent read contention before introducing a shared cancelable worker gate. | Potential resource containment. | Medium: gating could delay previews behind long metadata reads. Deferred pending evidence. |
| P2 | Import preview rejects the whole confirmed plan if any source changed; Update already handles item failures independently. | Keep verified-preview semantics for this change; design a separate explicit partial-import contract with refreshed preview and scanner-scoped outcomes. | Future accessible-scanner continuity without silently importing an unreviewed plan. | Medium–high: do not weaken existing stale-plan tests or copy verification. Deferred. |
| P2 | Parsing currently repeats some document normalization/classification between content and measurement passes. | Benchmark a trusted internal parsed-document reuse path before changing parser interfaces. | Possible cold-read CPU reduction. | Medium: provenance and public input trust are more important than speculative speed. Deferred. |
| P2 | SHA-256 validates package consistency, but an attacker replacing both files and manifest is outside that guarantee. | Document an IT-approved signing design: Authenticode for host/PowerShell, signed package manifest with pinned public key/rotation and a controlled release signing identity. Keep current hashes. | Stronger publisher authenticity where hospital IT accepts the signer. | Requires key custody, trust/rotation and release-policy decisions; do not pretend unsigned packages are authenticated. No signing-policy change in this branch. |
| P2 | Classic has fixed minimum windows that exceed a 1366×768 screen’s logical area at 200% scaling; existing layout checks are not high-DPI proof. | Retain the fallback and scope browser scaling evidence honestly; design native fit/scroll changes with actual Windows DPI testing. | Future accessible Classic controls at extreme scaling. | Deferred: a late unverified WPF layout change risks the fallback. |
| P3 | Large PowerShell modules and long, appended CSS/JavaScript rules are difficult to maintain. Existing upgrader only admits specific JavaScript asset names. | Extract small pure helpers within the supported asset boundary and refactor only touched logic; avoid a rewrite/new runtime dependency. | Smaller review surface and fewer upgrade regressions. | Low for local refactors, high for wholesale split. Incremental only. |
| P3 | Monthly, Trends, Folders and Exports already separate receipt, detected sections, formal evidence, contexts and scope. | Preserve those distinctions; improve labels/layout and empty states using existing capabilities. | Simpler workflows without duplicate features. | No invented results, thresholds, sign-off or new evidence model. |

## Implementation phases and validation boundary

1. Establish a pinned baseline and synthetic performance workloads; record the audit and inspect existing behavior.
2. Implement bounded list rendering/search, preview metadata optimization, readability/accessibility and unambiguous filing labels in separate commits.
3. Harden state/update/backup validation with failure and preservation regressions; improve PR validation and maintenance documentation.
4. Run applicable existing suites plus targeted regressions, repeat the exact synthetic benchmarks, capture all eight workspaces in light/dark and test effective scaling sizes. Run hosted Windows PowerShell 5.1, Edge, WPF and portable reader checks on this branch where available.
5. Record actual outcomes, limits and rollback instructions and open a pull request. Do not merge, publish a release or install on a workplace machine.

No external application dependency is added. No PDF, scanner source, clinical evidence, credential or live configuration is used in public tests. Linux development checks and effective-viewport simulations do not establish actual Windows DPI, scanner connectivity, hospital IT approval, or workplace performance. Existing native evidence remains historical until a fresh branch run completes.

## Implemented branch outcome

The branch implements a cohesive imaging-console visual system with bundled CT illustrations, bounded Reports rendering, cached metadata/filtering and stable Reports/Review DOM reuse; larger centralized typography, contrast, session-scoped density, small-window layout and accessibility fixes; expandable Monthly scanner summaries; clearer filing labels; readable nonempty Trends with local panning; fresh validated PDF membership without dashboard projections; ambiguous-state rejection and safe CSV projection; safer backup restore/update rollback and launcher parity; corrected Classic version text; PR validation and complete independent test reporting. No clinical parser, evidence model, safety/resource limit or runtime dependency is changed.

Measured comparisons, memory tradeoffs, actually executed development scope and remaining limitations are in [the branch validation report](ENGINEERING-VALIDATION.md). [Updated previews](ENGINEERING-SCREENSHOTS.md) cover all eight workspaces. Fresh hosted Windows results are attached to the PR once complete; published 5.6.0 reports are not relabeled as new evidence.
