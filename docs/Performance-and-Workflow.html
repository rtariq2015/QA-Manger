CT QA: workflow and performance decisions

Research and implementation notes for the portable offline 5.3 workspace. External links below are optional references; the program loads no external design assets, AI service or chart library.

A workflow with one job per screen

Today answers what arrived and what still needs attention. Reports searches saved files. Review gives the PDF most of the space and offers Approve or Disapprove for its proposed filing type. Exports builds a complete package with independent filters. Trends follows printed measurements back to their source pages. Settings groups connections and occasional maintenance tools. Local SVG icons, semantic color tokens and matching light/dark states give the screens a consistent appearance.

Daily receipt, document filing and clinical approval are different facts. The interface keeps their labels separate. Color reinforces a status that is also written in text; charts include a data table and source links.

Performance choices supported by the current evidence

The native comparison runs the same synthetic reports through both readers, measures isolated cold reads and verifies agreement. Standard is the first Automatic reader because it was faster in that comparison. Python remains a bundled alternate. The evidence does not establish a Python speed increase, hospital-network throughput or reduced memory use. Exact final-run results are recorded in the testing report.

Unchanged successful readings stay cached. Background reading uses one PDF per checkpoint, lower process priority, foreground priority between PDFs, a short yield, and Pause/Resume. A user batch is bounded at 20 actual read attempts. This improves opportunities to interact with the application; it does not eliminate CPU, storage or network work. Metadata and snapshot rebuilding still have a cost on a large archive.

The scrolling viewer loads visible/nearby page images with bounded concurrent requests and a bounded revocable image cache. It cancels obsolete requests when a different report is opened. Trends reads existing cache metadata and starts no hidden PDF work. Explicit history-reading actions are bounded.

Measurements and future options

Water CT and image-noise series remain separate by scanner, mode, system and slice. The graph retains unusual readings and printed limits. Unsupported, incomplete or conflicting measurements are withheld. Change is latest minus first within the chosen period, not a calibrated drift diagnosis. Comparable scan protocols remain necessary.

A persistent worker could reduce repeated process startup, but requires a separate measured experiment with per-document timeouts, cancellation and provenance checks. SQLite indexing should be considered only after measuring a JSON metadata bottleneck; its WAL mode is unsuitable for a shared network filesystem. Additional OCR, native PDF engines and AI models would need their own portable compatibility, licensing and workload tests before inclusion.
