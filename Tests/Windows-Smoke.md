# Windows workstation validation still required

The archive tests can execute on PowerShell 7 on Linux. That does **not** establish that Windows PowerShell 5.1, WPF rendering, Windows network authentication, or hospital endpoint policy works. Perform these checks on an approved Windows workstation before department use. The test runner creates its own synthetic PDFs in a temporary folder; it never points at the scanners.

1. Extract the entire ZIP into a normal user-writable Desktop folder. Keep all subfolders together. Use a direct, user-writable local Windows disk or removable USB archive; network/UNC archives and mapped network destinations are deliberately rejected so an archive cannot alias a scanner source. Launch the clearly named root launcher. Startup failures must remain visible. Do not change execution policy or endpoint protection to make it run; use hospital IT approval where required.
2. In Windows PowerShell 5.1, run the test script below from the extracted product folder. No administrator rights or third-party test framework is required. Confirm the JSON says `WindowsPowerShell51ActuallyRun: true`, every scenario passes, and `Failed: 0`.

   ```powershell
   powershell.exe -NoProfile -File .\Tests\Run-Tests.ps1 -OutputPath "$env:TEMP\CTQA-Windows-Test-Results.json"
   powershell.exe -NoProfile -STA -File .\App\Start.ps1 -ValidateLayout
   ```

3. Inspect the actual dashboard at 100%, 125%, 150%, and 200% display scale. Resize to its minimum window size. Confirm no clipped labels or inaccessible controls. Keyboard tab order, focus outlines, editable Advanced Settings, report filtering, and scrollbars must remain usable. Confirm no technical commands are needed for normal use.
4. Use only a synthetic archive and local synthetic PDF folders for initial UI checks. For this developer acceptance check, back up `Config/Settings.json`, then set its three source `Path` fields to absolute synthetic local directories and `ArchiveRoot` to a separate synthetic local folder before opening the app. The normal Advanced Settings screen requires UNC scanner paths; do not save its path fields over the temporary local fixture configuration. Restore the backed-up settings afterward. Complete First-Time Setup: choose archive, inspect the preview, cancel, and verify no PDFs were copied. Run it again and confirm import. Afterward, First-Time Setup should be de-emphasized, Update Reports should be obvious, and Open Reports Folder should open the selected archive's Reports folder.
5. Run Update Reports twice. The second update must skip unchanged content. While a large synthetic import runs, move/resize the window and open a separate app. Confirm the UI remains responsive and progress stays visible. Request cancellation and confirm it stops at a safe point. Restart; no incomplete staging file may appear as an archived report.
6. To validate a real mid-transfer interruption, use a large synthetic PDF only. End the application process during transfer, reopen it, and rerun the update. Confirm no partial PDF is indexed as complete, existing verified reports remain intact, and the next update either completes recovery or clearly explains what needs attention. This process-kill test was not executed on Windows in the build environment.
7. Review a pending synthetic Monthly candidate. Confirm the preview leaves its category unchanged; applying requires an identified reviewer and reason. Confirm its copied hash is preserved, its reviewed category is searchable, and an unchanged update retains the decision. A changed source revision must require new review.
8. Corrupt one byte of a synthetic archived PDF and run Full Integrity Audit. Confirm the attention item identifies that PDF and does not mark the audit successful. Source PDFs must remain untouched. An integrity audit is manual; there is no scheduled monitoring.
9. With IT-authorized scanner access, confirm each of the three UNC paths. Disconnect one source from the test configuration and run Update Reports: the other scanners must continue and the unavailable scanner must be clearly identified. Source connectivity and missing archive evidence must have distinct wording.
10. Validate network reconnection on Windows with hospital IT: a free preferred letter; an unrelated existing letter; the correct existing mapping; wrong credentials; Windows error 1219; and a read-denied share. Confirm no unrelated mapping/session is removed or replaced. Inspect logs/settings for absence of passwords. Native Windows credential prompts and WNet calls were not executed on Linux.
11. Reuse a **copy** of a legacy archive. Preview legacy adoption/migration and cancel once. Confirm no original archive files are moved, renamed, deleted, or edited, and an explicit migration produces verified, indexed copies. Legacy filename-only Monthly labels must not become new confirmed monthly evidence without review.
12. If testing against the original scanner locations, compare a read-only before/after source inventory (path, length, modification time, SHA-256 for sampled files). The application should only read these locations. Keep fixture corruption and termination experiments isolated from real QA records.

Retain the Windows test JSON and record workstation OS/build, PowerShell version, DPI, launch-policy outcome, and tester/date. These are workstation validation results, not a determination of clinical QA compliance.
