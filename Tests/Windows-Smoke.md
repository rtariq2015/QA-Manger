# Workstation acceptance still required

Current cloud results include PowerShell 7 on Linux and a separate hosted Windows PowerShell 5.1 run; see `Current/Windows/Summary.json`. That does **not** establish that Windows PowerShell 5.1, WPF rendering, Windows network authentication, or hospital endpoint policy works. Perform these checks on an approved Windows workstation before department use. The test runner creates its own synthetic PDFs in a temporary folder; it never points at the scanners.

1. Extract the entire ZIP into a normal user-writable Desktop folder. Keep all subfolders together. Use a direct, user-writable local Windows disk or removable USB archive; network/UNC archives and mapped network destinations are deliberately rejected so an archive cannot alias a scanner source. Launch the clearly named root launcher. Startup failures must remain visible. Do not change execution policy or endpoint protection to make it run; use hospital IT approval where required.
2. In Windows PowerShell 5.1, run the test script below from the extracted product folder. No administrator rights or third-party test framework is required. Confirm the JSON says `WindowsPowerShell51ActuallyRun: true`, every scenario passes, and `Failed: 0`.

   ```powershell
   powershell.exe -NoProfile -File .\Tests\Run-Tests.ps1 -OutputPath "$env:TEMP\CTQA-Windows-Test-Results.json"
   powershell.exe -NoProfile -STA -File .\App\Start.ps1 -ValidateLayout
   ```

3. Inspect the actual dashboard at 100%, 125%, 150%, and 200% display scale. Resize to its minimum window size. Confirm no clipped labels or inaccessible controls. Keyboard tab order, focus outlines, editable Advanced Settings, report filtering, and scrollbars must remain usable. Confirm no technical commands are needed for normal use.
4. Use only a synthetic archive and local synthetic PDF folders for initial UI checks. For this developer acceptance check, back up `Config/Settings.json`, then set its three source `Path` fields to absolute synthetic local directories and `ArchiveRoot` to a separate synthetic local folder before opening the app. The normal Advanced Settings screen requires UNC scanner paths; do not save its path fields over the temporary local fixture configuration. Restore the backed-up settings afterward. Complete First-Time Setup: choose archive, inspect the preview, cancel, and verify no PDFs were copied. Run it again and confirm import. Afterward, First-Time Setup should be de-emphasized, Update Reports should be obvious, and Open Reports Folder should open the selected archive's Reports folder.
5. Run Update Reports twice. The second update must skip unchanged content. While a large synthetic import runs, move/resize the window and open a separate app. Confirm the UI remains responsive and progress stays visible. Request cancellation and confirm it stops at a safe point. Restart; no incomplete staging file may appear as an archived report.
6. To validate a real mid-transfer interruption, use a large synthetic PDF only. End the application process during transfer, reopen it, and rerun the update. Confirm no partial PDF is indexed as complete, existing verified reports remain intact, and the next update either completes recovery or clearly explains what needs attention. This process-kill test was not executed on Windows in the build environment.
7. Review a pending synthetic Monthly candidate. Confirm the preview leaves its category unchanged; applying requires an identified reviewer and reason. Confirm its copied hash is preserved, its reviewed category is searchable, and an unchanged update retains the decision. A changed source revision must require new review.
8. Corrupt one byte of a synthetic archived PDF and run Full Integrity Audit. Confirm the attention item identifies that PDF and does not mark the audit successful. Source PDFs must remain untouched. An integrity audit is manual; there is no scheduled monitoring.
9. With IT-authorized scanner access, confirm each of the three UNC paths. Disconnect one source from the test configuration and run Update Reports: the other scanners must continue and the unavailable scanner must be clearly identified. Source connectivity and missing archive evidence must have distinct wording.
10. Validate network reconnection on Windows with hospital IT: a free preferred letter; an unrelated existing letter; the correct existing mapping; wrong credentials; Windows error 1219; and a read-denied share. Confirm no unrelated mapping/session is removed or replaced. Inspect logs/settings for absence of passwords. Native Windows credential prompts and WNet calls were not executed on Linux.
11. Reuse a **copy** of a legacy archive. Preview legacy adoption/migration and cancel once. Confirm no original archive files are moved, renamed, deleted, or edited, and an explicit migration produces verified, indexed copies. Legacy filename-only Monthly labels must not become new confirmed monthly evidence without review.
12. If testing against the original scanner locations, compare a read-only before/after source inventory (path, length, modification time, SHA-256 for sampled files). The application should only read these locations. Keep fixture corruption and termination experiments isolated from real QA records.

Retain the Windows test JSON and record workstation OS/build, PowerShell version, DPI, launch-policy outcome, and tester/date. These are workstation validation results, not a determination of clinical QA compliance.

## Report filters, export, and the readable folder view

The following checks apply to the added report tools and still require real Windows UI execution. The automated export and mirror tests are separate from a WPF interaction test.

13. Run the synthetic report tools and connection tests under Windows PowerShell 5.1 as well:

    ```powershell
    powershell.exe -NoProfile -File .\Tests\Run-ExportTests.ps1 -OutputPath "$env:TEMP\CTQA-Windows-Export-Results.json"
    powershell.exe -NoProfile -File .\Tests\Run-BrowseTests.ps1 -OutputPath "$env:TEMP\CTQA-Windows-Browse-Results.json"
    powershell.exe -NoProfile -File .\Tests\Run-ConnectionTests.ps1 -OutputPath "$env:TEMP\CTQA-Windows-Connection-Results.json"
    ```

14. With an isolated synthetic archive open in the real Reports view, combine scanner, year, month, and QA type filters. Confirm December of one year does not include the previous year's December or November. Search for human labels such as `CT Flash` and `Daily QA`. Pending Monthly and confirmed Monthly must remain distinct. Use the Multiple years chooser to check two different years, then choose December. Confirm both chosen Decembers appear and November remains excluded. Clear filters, change filter values with the keyboard, and confirm the visible count and export button count always agree.
15. Select a month with multiple testing sessions and duplicate original filenames. Click Export, inspect the selection count and destination, and save a new ZIP to a local folder or USB drive. It must include **every matching report**, with separate entries for distinct sessions, and a readable report list preserving original filenames and hashes. Open the finished export folder. Extract the entire ZIP, then open `QA Report Summary.html` while disconnected from the network. Verify year/month/scanner/category counts and every PDF link, including duplicate sessions. Keep the summary and its PDF folders together. An export is a selection of archive evidence and must not imply that a month's clinical QA is complete.
16. Cancel a large synthetic export while progress is visible. Confirm no completed ZIP or partial staging file remains and the UI is usable. Retry, verify the ZIP opens, then choose an already-existing ZIP filename and confirm its bytes are preserved. Repeat export with the scanner paths unavailable: previously archived and verified PDFs should still export. Synthetic missing or corrupted archived reports must cause a clear export failure with no completed ZIP.
17. Open Reports Folder and inspect the `Browse Reports` view: scanner, year, readable month, QA category, and human-readable PDF names. This is a separate copy of the indexed archive. On synthetic data only, edit one browse copy and refresh the view. Confirm the indexed archive PDF and hash remain unchanged and the edited browse copy is preserved with a clear attention result. Add an unrelated file to the browse folder and verify refresh does not delete it.
18. Review a synthetic Monthly candidate, then refresh the readable folder view. The current report should appear in its reviewed category; an unchanged ledger-owned old category copy should be preserved in private browse history. Existing user-edited copies must be retained. Cancel a large readable-view refresh and retry; no half-written PDF may appear as a finished report.
19. With First-Time Setup already completed and update-on-open enabled, reopen the application. Confirm the dashboard paints first and one update then starts with usable progress and cancellation. Resizing or repeated rendering must not start another update. Uncheck the startup-update preference, save, and reopen: no scanner update should start. A new archive must still require setup preview and confirmation before its first import. This preference does not install periodic monitoring or a scheduled task. With the preference off, run Update Reports manually and confirm the readable view reflects newly committed records. A readable-view or export failure must not misrepresent the scanner archive update as clinically incomplete.

20. On synthetic connection settings, add a fourth scanner with a distinct name, stable safe ID, path, and preferred drive letter. Confirm its status card, report count, filter entry, exported display name, and readable folder appear while the original scanners remain intact. Rename its display label and confirm archive report identities and hashes do not change. A duplicate ID, name, drive letter, source path, or unsafe identity must be rejected clearly. Removing or changing an ID with archived records must not orphan those records.
21. Run the connection suite's Windows credential branch with its randomly generated **synthetic** credential. Confirm `WindowsDPAPIActuallyRun` is true and the test passes: protected save/load, no plaintext password in the credential envelope, changed username/path and expected-username mismatch cannot silently reuse it, and explicit removal works. Actual Windows DPAPI protection was not executed in the Linux build environment. In the real settings UI, use the PasswordBox, verify blank password retains only a matching connection's saved sign-in, and confirm Forget saved sign-in removes it. Saved sign-ins belong to the current Windows account and workstation; copying the portable folder to another workstation requires re-entry. No real credential should be entered into test fixtures or command arguments.

22. In an isolated synthetic archive, save a scanner connection with a new root path representing a changed server/IP/folder while keeping its scanner ID. Identical bytes at the same relative source path should rebind to the existing report identity, archive PDF, and reviewer evidence. A subsequent cached update should skip it. Touch the synthetic source timestamp without changing bytes and confirm no duplicate appears. Changed bytes must become a retained revision requiring fresh Monthly confirmation; identical basenames in different relative folders or ambiguous prior-root matches must not be silently merged. Changed connection paths must not silently receive credentials bound to the previous source.

23. Configure an approved Monthly component checklist in Advanced settings; the application must not invent a department protocol. On synthetic PDFs, confirm only MTF in one reviewed report and only slice thickness in another report for the same scanner and month. Coverage should be partial after the first decision and show all configured items represented only after the second. A combined reviewed PDF may cover both items. Pending hints, unreviewed candidate PDFs, another scanner's report, another month's report, and a changed file revision must not supply confirmed components. With no checklist configured, an old Monthly label must not be described as a complete checklist. Export just one PDF from a full archive month: the offline HTML must describe only that selected PDF's partial coverage; exporting both may describe the selected union. Verify the actual review checkboxes, missing-item wording, and one summarized monthly attention item in the real Windows UI.
