What these tests establish

  • Safe initial preview/import, metadata skips, changed-file revisions, SHA-256 verification, archive audit, concurrent-writer locking, interrupted transfers, crash recovery, and preservation of original PDFs.
  • Month/year/multi-year/scanner/type/text filters; all matching identities exported; every ZIP PDF independently read back and hashed; clear collision handling; no-overwrite publication and cleanup after cancellation or failure.
  • Standalone escaped HTML summary with relative PDF links, spreadsheet-safe report list, and Monthly coverage calculated from selected reports only.
  • Independent readable PDF copies, real metadata-cache skips, owned-history recovery, and preservation of edited/unrelated browsing files.
  • Additional scanners, editable source information, stable identities after approved address changes, and credential failures isolated per scanner. Non-Windows credential writes are refused before creating files.
  • Explicit reviewed component unions across combined or separate Monthly PDFs. Empty checklists, pending files, old category labels and changed PDF bytes cannot falsely establish complete Monthly documentation.
  • The actual extracted startup callback invokes one update only for eligible established archives; opt-out and first-setup safeguards work in a synthetic harness.
  • PDF text extraction through the bundled runtime from compressed multi-page fixtures, image-only/blank handling, encrypted-file errors, bounds, offline reading, saved-hash verification and archive-lock protection. Text reading never modifies classifications.

Parsing, compatibility and package checks

All seven application scripts/modules and the actual embedded worker script parse with the PowerShell 7.4.19 parser. Main XAML contains 66 unique named controls; its XML, eight dialog fragments and scanner-editor XML are well formed, with no unresolved static named-control references. This is source validation, not native WPF layout or interaction validation.

PSScriptAnalyzer 1.25.0 targets PowerShell 5.1 syntax and Windows 5.1 command/type profiles. It reports zero unexpected findings and two expected WinForms type notices: the types are explicitly loaded at runtime rather than included in the analyzer's default-loaded profile. See compatibility evidence. Script UTF-8 BOMs, safe launcher structure and static rules are recorded in Package-Checks.json.

All 12 bundled PDF DLL hashes match App/Lib/PdfPig/Integrity.json. PdfPig 0.1.16 runtime assemblies, Microsoft dependencies, licenses and notices are included. The optional text reader requires .NET Framework 4.7.2 or newer on Windows; it does not install or download a framework.

Observed local performance

One run used 300 synthetic PDFs of approximately 50 KiB distributed across three local source folders. Preview: 1.08 s; initial archive import: 7.79 s; unchanged archive update: 1.23 s. All 300 reports were skipped and zero recopied.

Building the readable view took 3.24 s; its unchanged refresh took 0.85 s, skipping 300 copies. These are Linux/local-disk observations, not Windows, SMB or hospital performance promises. The two phases run sequentially in the application.

Operational scope

The app runs from a folder on the Windows computer. USB is an optional report-package destination. Once setup is complete, opening the app performs one update by default; the preference can be disabled. No periodic scanning, scheduled task or service is installed, and no scanner update continues after the app closes.

Monthly checklists are empty by default because the department/QMP-approved procedure determines required items. The app tracks reviewed documentation, not clinical pass/fail or compliance. Its Siemens reference guide links version-specific official manuals and current ACR support guidance without replacing the applicable hospital procedure.

Managed archives, readable copies and exports use local disks/USB; network/mapped destinations and linked paths are rejected. Fast updates depend on metadata, so source changes deliberately preserving size and timestamps need additional investigation. Full integrity audit checks saved PDFs against indexed hashes, not unchanged scanner-source bytes. Text reading has file/page/text limits and cooperative cancellation/time checks between parser calls; an individual parser call cannot be forcibly interrupted.

Evidence contains synthetic reports only. No real scanner, hospital credentials or patient PDFs were accessed during this validation. Untested Windows behavior is not described as verified.
