Caching improvements for repeated browsing:

- Reports and Exports share recent filter results, bounded to eight selections and 80,000 record references. Today reuses its saved-report links, filing counts and available-year list while the saved records are unchanged.
- The receipt calendar reuses recent month/scanner models, bounded to 12 selections and 40,000 report-ID references. Its existing receipt calculations and Daily/Monthly distinction are unchanged.
- Folders, Exports and the current calendar keep their existing controls when their data and selection have not changed, avoiding complete DOM reconstruction and retaining focus/open folders.
- Trends reuses recent query results in an eight-key, 2 MiB metadata cache. Native PDF previews reuse recently viewed pages within the existing shared 20-page/30 MiB image budget. Both expire cached results after five minutes; archive and relevant data changes invalidate them.
- Retain the Monthly cache added in 5.7.16, persisted PDF analysis cache, verified readable-folder reuse and in-memory host snapshot. No new runtime dependency, new display feature or archive-format change.

These are session caches for read-only browsing, not cached success results for filing, Undo, copying, backups, updates or sign-in. Their verification and transaction handling remain in place. First-time loads still perform the necessary backend work; restarting clears browser-memory caches. Out-of-band filesystem changes are not detected instantly by snapshots, and original-PDF opening/new uncached page requests retain the existing source checks.
